# Time Warp v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Switch the warp line to HyperWarp's meaning (top = live, height = how far back, 45° = stopped). Add 7 four-knob profiles on picture and sound, an Output section, graph tools, dice with locks, and the warp line as a modulation source. Make Dry/wet routable for every modulator.

**Architecture:**
- The time-model change is confined to `warpMath.ts` and its inline port in `public/worklets/warp-processor.js`. Everything downstream already consumes `delaySeconds`.
- **Profiles:**
  - On the audio side they become a grain engine in the worklet, with per-profile processing.
  - On the video side each profile is one fragment shader fed by the existing frame ring.
- **Modulation:** a `'warp'` source in `useContinuousModulation`, plus an `effectMix` branch in `applyModulation`.

**Tech Stack:** React 19, TypeScript, zustand 5, three.js, Web Audio AudioWorklet, puppeteer harnesses in `.superpowers/sdd/`.

**Spec:** `docs/superpowers/specs/2026-10-08-time-warp-v2-design.md`. It builds on `docs/superpowers/specs/2026-10-08-time-warp-design.md`.

**Base:** branch `feat/time-warp` at `e5487a0`, which has v1 Tasks 1 to 5 done.

## Global Constraints

**Time model**, verbatim from the spec:
- `x′ = x^(2^(−1.5·skew))`
- `y′ = amount · f(x′)`
- `delay = y′ · L_seconds`, clamped to 8 s, with no modulo.
- y = 0 is drawn at the top and is live.
- Speed is `1 − dy′/dx`.
- The default line is `[{x:0,y:0},{x:1,y:0}]`.

**Settings:**
- Length is ½, 1, 2, 4, 8 or 16 beats.
- Quantize (store key `snap`) is 0 = Off, 1/4, 1/8, 1/16, 1/32 or 1/64.
- Amount runs 0 to 1, Skew −1 to 1, Mix 0 to 1.

**Profiles:**
- The ids are `clean`, `flange`, `degrade`, `filterspam`, `harmonicer`, `fauxcoder` and `lofizzly`.
- The UI names are Clean, Flange, Degrade, Filter Spam, Harmo-nicer, Fauxcoder and Lo-fizzly.
- Each profile has 4 knobs, 0 to 1. The knob names and neutral values are in spec §3.
- `profileParams: Record<ProfileId, [n,n,n,n]>`.

**Output:**
- Low cut runs 20 Hz to 2 kHz, high cut 500 Hz to 20 kHz, both 12 dB/oct, applied to the wet signal only.
- Level runs −24 to +6 dB.
- Video uses a soft luminance key for Band and a wet brightness gain for Level.

**Neutral rule:**
- With neutral knobs, a flat line at the top, Mix at 1 and Output open, the audio is within 1e-4 of the input.
- Under the same conditions the video is the live texture object itself.

**Bypass:** warp off means no capture, no pass and no worklet, as in v1.

**Performance:**
- The frame rate with the warp on is within 5% of the frame rate with it off.
- Each profile renders 10 s of stereo at 48 kHz offline in under 1.5 s.

**Storage:**
- `localStorage` keys are `seg.warp.lines` and `seg.warp.locks`. Every access is wrapped in try/catch.
- Locks are never saved in banks or presets.

**Modulation:**
- The source id is `'warp'`. Its value is `amount·f(skewPhase(getHeardWarpPhase(), skew))`.
- It is computed whenever a route uses it, whether or not the warp effect is on.
- The Dry/wet param id is `<effectId>.effectMix` and is written through `setEffectMix`.

**UI and copy:**
- Use theme tokens: `--warp`, `--warp-ink`, `--warp-grid`, `--warp-identity`.
- Use IBM Plex in normal case. No em dashes.
- Use muted text only on panel or raised surfaces; use `--text-secondary` on control and hover surfaces.
- New layout components are `React.memo` with narrow selectors. Never call `useActiveEffects`.

**Harness rules:**
- Run with `PATH=/opt/homebrew/bin:$PATH`.
- Kill and restart Vite on :5173 before every run.
- Use fire-and-poll for async page work.
- seg-verify "snapshot roundtrip" fails on base too; ignore it.
- Leave Vite running when finished, because the user tests on it.

## Review Focus

1. **Turning the warp on with the default line must change nothing.** Flat at the top means delay 0 and the live texture passes straight through. A regression here makes the effect look broken. This is pinned in Task 1 (maths) and Task 4 (video same-object check).
2. **Jumps the line walk does not see.** Steps down in the new meaning are the common case. The video jump detection (`WarpCompositor.detectJump`) and the audio crossfade must still fire on them. This is pinned in Task 4 (degrade still holds on Stutter build) and Task 3 (no click at a step with Clean).
3. **Storage unavailable.** In private mode, saving a line or the locks must not throw. The lists come back empty. This is pinned in Task 2 and Task 5.
4. **Dry/wet modulation fighting the user's drag.** When a route writes `effectMix`, a manual drag of the bar sets the base value as other params do and must not throw or flicker. This is pinned in Task 6.
5. **A ½-beat length at a high BPM gives a very short loop.** At 200 BPM, ½ beat is 0.15 s. The ring, the thumbnails and the jump walk must stay finite and stable. This is pinned in Task 1 (loopSeconds and delay) and Task 4 (a 200 BPM ½-beat run with no errors).
