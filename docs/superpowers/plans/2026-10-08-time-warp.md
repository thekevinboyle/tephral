# Time Warp Sequencer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A HyperWarp-style time-warp sequencer. A drawn line maps loop phase to loop read position, and both the source video and the audible audio play along that line in sync. It is edited in a new Warp tab and shown as a Time warp card at the head of the device chain.

**Architecture:**
- **Maths:** one pure module, `src/effects/warp/warpMath.ts`. It covers the line model, the lookup table, phase and delay, presets and randomize. Both the video side and the audio side use it, and the audio side gets it as a lookup table posted to an AudioWorklet.
- **Video:** a GPU frame ring, `WarpFrameBuffer`, with a profile compositor, `WarpCompositor`. It sits between the media texture and `pipeline.setInputTexture` in `Canvas.tsx`.
- **Audio:** an AudioWorklet, `public/worklets/warp-processor.js`, inserted between each audible source and its analysers and speakers in `useUnifiedAudioAnalysis`.
- **Clock:** `src/effects/warp/warpClock.ts` derives phase from the AudioContext time and the sequencer BPM, so picture and sound share one clock.

**Tech stack:** React 19, TypeScript, zustand 5, three.js 0.182, Web Audio (AudioWorklet), Vite 7.

**Spec:** `docs/superpowers/specs/2026-10-08-time-warp-design.md`. Mockup: `docs/superpowers/specs/assets/2026-10-08-time-warp/mockup.html?d=A`.

## Global Constraints

**Time model.** Copied verbatim from the spec:
- `y′ = x + amount·(f(x) − x)`
- `x′ = x^(2^(−1.5·skew))`
- `delay = ((x′ − y′) mod 1)·L_seconds`
- delay is clamped to 8 s
- the line's lookup table has 1024 points
- y = 0 is drawn at the top

**Memory.**
- Video frames are captured at 30 fps.
- They are stored with the long side 512 px and an 8 s ring, allocated only while the warp is on.
- The audio ring holds 8 s of stereo.

**Bypass.** When the warp is off, there is no frame capture, no extra pass and no worklet in the graph. The live texture and the original audio graph are used exactly as before.

**Settings.**

| Setting | Values |
|---|---|
| Length | 1, 2, 4, 8 or 16 beats |
| Snap | 1/4, 1/8, 1/16, 1/32 or 1/64 |
| Amount | 0–1 |
| Skew | −1 to 1 |
| Mix | 0–1 |
| Applies to | `both`, `video` or `audio` |

**Profiles and their knobs (0–1):**

| Profile | Knobs |
|---|---|
| `clean` | Smooth |
| `smear` | Grain, Blend |
| `degrade` | Rate, Crunch |

**Audio playback.**
- Audible sources only: an audio file, or a video file's soundtrack when Audio is set to Video.
- Mic and system input are never routed to the speakers.

**UI.**
- Use theme tokens. Add one new token, `--warp: #e8c35a`.
- IBM Plex Sans and Mono, normal case, no em dashes in copy.
- Muted text only on panel and raised surfaces; use `--text-secondary` on control and hover surfaces.

**Persistence.** Add a `warp?:` key in `BankSnapshot` and the preset library. `applySnapshot(undefined)` resets to the defaults.

## Review Focus

1. **Tempo or length changes while the warp is running.** Phase must stay continuous: no jump to 0, no burst of clicks. Re-anchor t0 so x is preserved. Covered by a Task 2 test.
2. **Switching the source while the warp is on** (file → webcam → none). The video ring clears and refills with no stale frames from the old source shown. The audio worklet is re-inserted into the new graph or removed. Covered by a Task 3 test and a Task 2 test.
3. **Lines with two points at the same x** (vertical jumps) and points at x = 0 and x = 1. Lookup-table sampling must stay well defined: a jump takes the later point's y at that x, and the line always spans 0 to 1. Covered by a Task 1 test.
4. **A video soundtrack becoming audible.** With Audio set to Video and a file source, sound plays once, through the warp. It must not double up with any earlier path, and it must stop when the source changes. Covered by a Task 2 test.
5. **GPU memory.** Turning the warp off, or changing resolution, releases the render targets. Toggling the warp 10 times must not grow the render-target count. Covered by a Task 3 test.

```ts
// src/effects/warp/warpMath.ts
export interface WarpPoint { x: number; y: number; bend?: number }   // bend: -1..1 curve of the segment ENDING at this point
export const LUT_SIZE = 1024
export function normalizePoints(pts: WarpPoint[]): WarpPoint[]       // sort by x (stable), clamp 0..1, ensure x=0 and x=1 exist
export function sampleLine(pts: WarpPoint[], x: number): number      // y at x; at duplicate x returns the LATER point's y
export function buildLut(pts: WarpPoint[]): Float32Array             // LUT_SIZE samples of sampleLine
export function skewPhase(x: number, skew: number): number           // x^(2^(-1.5*skew)), endpoints fixed
export function warpedY(lut: Float32Array, x: number, amount: number): number   // x + amount*(lut(x) - x)
export function delayFraction(xs: number, y: number): number          // ((xs - y) mod 1), in [0,1)
export function delaySeconds(opts: { phase: number; lut: Float32Array; amount: number; skew: number; loopSeconds: number; maxSeconds?: number }): number
export function loopSeconds(lengthBeats: number, bpm: number): number // lengthBeats * 60 / bpm
export const PRESETS: Record<string, WarpPoint[]>                     // Straight, Stutter build, Half time, Freeze hits, Reverse, Tape stop, Scratch, Rearranger
export function randomLine(snap: number, rand?: () => number): WarpPoint[]
```

```ts
// src/stores/warpStore.ts
export type WarpProfile = 'clean' | 'smear' | 'degrade'
export type WarpApplies = 'both' | 'video' | 'audio'
export interface WarpSnapshot { enabled: boolean; points: WarpPoint[]; amount: number; lengthBeats: 1|2|4|8|16; snap: number; skew: number; profile: WarpProfile; params: { smooth: number; grain: number; blend: number; rate: number; crunch: number }; appliesTo: WarpApplies; mix: number; presetName: string | null }
export const WARP_DEFAULTS: WarpSnapshot                             // enabled false, PRESETS.Straight, amount 1, length 4, snap 1/16, skew 0, clean, smooth .3 grain .4 blend .5 rate .5 crunch .3, both, mix 1
export const useWarpStore: UseBoundStore<StoreApi<WarpSnapshot & {
  lut: Float32Array                                                  // derived, rebuilt on every points change
  setEnabled(v: boolean): void; setPoints(p: WarpPoint[]): void; patch(p: Partial<WarpSnapshot>): void
  loadPreset(name: string): void; randomize(): void
  applySnapshot(s: WarpSnapshot | undefined): void; getSnapshot(): WarpSnapshot
}>>
```

- [ ] **Step 1: Write the `warpmath` check.** It runs in the page via `import('/src/effects/warp/warpMath.ts')`. It asserts:
  - **Identity:** the identity line `[{x:0,y:0},{x:1,y:1}]` gives `delaySeconds` of 0 at phases 0, 0.3 and 0.99.
  - **Freeze:** `[{0,.25},{1,.25}]` at phase 0.75 with a 2 s loop gives 1.0 s. At phase 0.1 it gives `((0.1−0.25) mod 1)·2` = 1.7 s.
  - **Reverse:** `[{0,1},{1,0}]` gives a read position `t − delay` that decreases as phase increases.
  - **Step:** points `{0,0},{.5,0},{.5,.5},{1,.5}` give `sampleLine(.5)` = 0.5, the later point (Review Focus 3).
  - **Amount 0:** gives delay 0 for any line.
  - **Skew endpoints:** `skewPhase(0, s)` = 0 and `skewPhase(1, s)` = 1 for s = ±1.
  - **8 s clamp:** a 16-beat loop at 60 BPM (16 s), freeze at 0, phase 0.9, gives 8 s.
  - **Normalisation:** `normalizePoints` adds x = 0 and x = 1 when they are missing.
  - **Presets:** every entry in `PRESETS` normalises to x from 0 to 1.
  - **Randomize:** `randomLine(1/16)` gives at least 4 points, all on the 1/16 grid in x.
- [ ] **Step 2: Run the check.** It fails because the module is missing.
- [ ] **Step 3: Implement.**
  - Implement `warpMath.ts` from the interfaces. A `bend` curve on a segment uses `t' = bend>0 ? t^(1+3·bend) : 1-(1-t)^(1-3·bend)` between its endpoints.
  - Presets use 8 to 16 points. Shape Tape stop as a curve from the diagonal into flat, and Scratch as a back-and-forth.
  - Implement `warpStore.ts`. It persists through the bank and preset snapshots in Task 5, not through zustand `persist`.
- [ ] **Step 4: Check it passes,** and run lint and the build.
- [ ] **Step 5: Commit.** `feat: warp time-model maths and store`

export function getWarpPhase(ctxTime: number): number                // 0..1 loop phase now
export function setWarpAnchor(ctxTime: number, phase?: number): void  // t0; when called with the current phase, keeps x continuous (tempo/length changes)

- **Worklet messages.** The worklet receives `{type:'lut', lut}`, `{type:'clock', t0, bpm, lengthBeats}` and `{type:'params', amount, skew, profile, smooth, grain, blend, rate, crunch, mix, active}`. Per sample it does the following:
  1. compute the phase from `currentTime + i/sampleRate`;
  2. compute the delay, using the same maths as `warpMath`, ported inline;
  3. read from the 8 s ring with linear interpolation;
  4. apply the profile;
  5. mix dry and wet.
- **Click guard.** A jump in read position larger than 10 ms crossfades over `smooth·30` ms.

### Task 3: Video warp

**Files:**
- Create: `src/effects/warp/WarpFrameBuffer.ts`, the GPU ring of `THREE.WebGLRenderTarget` objects at long side 512, captured at 30 fps with timestamps
- Create: `src/effects/warp/WarpCompositor.ts`, which owns the buffer and renders the selected frame or frames through the profile shader into an output render target
- Create: `src/effects/warp/warpShaders.ts`, the profile fragment shaders:
  - **clean:** a single frame, crossfading to the previous read for `smooth·4` frames after a jump;
  - **smear:** a weighted blend of up to 6 frames around the read point, with Grain choosing the span and Blend the weight falloff;
  - **degrade:** frame-hold at `4 + (1−rate)·26` fps, plus posterize and pixelate scaled by Crunch.
- Modify: `src/components/Canvas.tsx`. Each animation frame, if the warp is enabled and `appliesTo !== 'audio'`:
  1. `compositor.capture(liveTexture, ctxTime)`;
  2. `out = compositor.render(getWarpPhase(ctxTime))`;
  3. `pipeline.setInputTexture(out)` and `setSourceTexture(out)`.

  When the warp is off, today's code runs unchanged. Apply the warp after the slicer (when the slicer is active, its texture is the "live" one).
- Modify: `.superpowers/sdd/layout-check.mjs` (add a `warpvideo` mode)
